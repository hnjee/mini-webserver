웹 요청 한 번의 여정: 소켓, 대기열, 버퍼

브라우저가 연결을 요청한 순간부터 닫힐 때까지, 어느 쪽 OS에 어떤 구조체와 버퍼가 생기고 사라지는지 단계별로 넘겨 보세요. 분홍 테두리가 방금 바뀐 것입니다.

프로그램 (사용자 공간)운영체제 (커널)방금 생기거나 바뀐 것

전체 단계

    꼭 기억할 네 가지

    • 연결은 선이 아니라 커널 안의 소켓

      양쪽 OS가 커널 메모리의 소켓 구조체에 기억하는 상태입니다. IP·포트 네 값, 시퀀스 번호, 상태, 송신·수신 버퍼가 담겨 있고, 라우터는 연결의 존재를 모릅니다.

    • 대기열은 연결을, 버퍼는 데이터를

      대기용 소켓에는 SYN 대기열과 accept 대기열이 있고, 연결용 소켓마다 송신 버퍼와 수신 버퍼가 하나씩 있습니다.

    • 소켓 = 커널의 실체 + 프로그램의 번호

      실체(구조체)는 커널 안에 있고, 프로그램은 OS가 준 파일 디스크립터 번호로 시스템 콜을 불러 요청합니다. read와 write는 내 메모리와 커널 버퍼 사이의 복사입니다.

    • 순서는 TCP, 경계는 HTTP

      OS는 요청이라는 단위를 모르고 바이트를 번호 순서대로만 넣습니다. 요청 하나가 어디서 끝나는지는 웹서버가 HTTP 규칙으로 잘라 냅니다.

    네 개의 층

    같은 높이끼리 대화합니다. 프로그램끼리는 HTTP로, OS끼리는 TCP/IP로 이야기하고, 세로 방향은 소켓 API가 잇습니다. 맨 아래 라우터와 스위치는 IP와 MAC만 보고 옮깁니다.

    [브라우저]      ←── HTTP ──→      [웹서버]
    │ connect·send·recv              │ listen·accept·read·write
[클라이언트 OS] ←── TCP/IP ──→  [서버 OS]
      └──── 라우터·스위치 (IP·MAC만 봄) ────┘

    OS가 스스로 연결을 시작하지는 않습니다. 합의(handshake)는 OS끼리 하지만, 시작하라고 시키는 건 프로그램의 connect()와 listen()입니다.

    서버 OS가 벗기는 순서

    각 계층은 자기 헤더만 확인하고 떼어 낸 뒤, 헤더에 적힌 값으로 다음 행선지를 고릅니다(역다중화).

    계층확인하는 것다음 행선지 단서
    NIC·드라이버목적지 MAC, FCS 오류 검사EtherType (0x0800 IPv4)
    IP목적지 IP, 체크섬, 조각 재조립Protocol (6 TCP, 17 UDP)
    TCPIP·포트 네 값으로 연결 찾기, 순서 정렬, ACK그 연결의 수신 버퍼
    웹서버read()로 복사 후 HTTP 파싱\r\n\r\n, Content-Length

    한 연결에 요청이 여러 개 오면

    보내는 쪽이 요청 1 다음에 요청 2를 보냈다면, 요청 2의 바이트는 시퀀스 번호가 전부 요청 1보다 뒤입니다. 패킷이 뒤바뀌어 도착해도 서버 OS는 빈틈이 메워질 때까지 뒷부분을 따로 보관만 하고, read()에는 앞에서부터 빈틈없이 이어진 부분만 내줍니다.

    도착 순서 (네트워크에서 뒤바뀜)

    요청1 ①요청1 ②요청2 ① 보관만요청1 ③

    수신 버퍼에서 read()가 보는 순서

    요청1 ①요청1 ②요청1 ③요청2 ①… 아직 안 옴

    “덜 왔는데 읽을 수 있다”는 건 뒷부분이 아직 안 왔다는 뜻이지, 중간이 비어 있다는 뜻이 아닙니다.

    그래서 웹서버는 이렇게 자릅니다

    읽은 걸 자기 버퍼에 이어 붙이고, 완성된 요청만 잘라 낸 뒤 남은 바이트는 다음 요청의 시작으로 남겨 둡니다.

    pending = b""
while True:
    data = sock.recv(4096)        # 커널 수신 버퍼 → 내 메모리
    if not data: break            # 0바이트 = 상대가 닫음
    pending += data
    while True:
        end = pending.find(b"\r\n\r\n")
        if end == -1: break       # 헤더가 덜 옴
        total = end + 4 + content_length(pending[:end])
        if len(pending) < total: break   # 본문이 덜 옴
        handle(pending[:total])   # 요청 하나 완성
        pending = pending[total:] # 나머지는 보관

    리눅스 기준으로 단순화한 그림입니다. 그림의 “연결용 소켓 (커널)”은 커널 안의 소켓 실체이고, 동그라미 숫자는 프로그램이 받은 번호입니다. 구조체 이름(request_sock, tcp_sock)과 포트·시퀀스 번호는 이해를 돕기 위한 예시입니다.
