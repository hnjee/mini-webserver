## 결정

### D-55. I/O 멀티플렉싱을 동시성 방식으로 선택한다
- 선택: **I/O 멀티플렉싱**으로 여러 연결을 다룬다.
- 이유: 사용자 선택. 대기 중인 연결이 처리 흐름을 묶는 문제를 먼저 풀고, 필요하면 이후 스레드 풀을 덧붙인다.
- 버린 선택지: 연결마다 `fork`, 스레드 풀 우선.
- 한계: 준비 알림만으로 파일 작업·긴 계산까지 논블로킹이 되지 않는다. 디스크 대기는 남는다.

### D-56. `epoll` 레벨 트리거로 기다리고, 한 차례에 정한 만큼만 처리한다
- 선택: Linux **`epoll` 레벨 트리거**, 모든 소켓 논블로킹. 연결은 한 차례에 소켓 `read` 1번·파일 조각 1번·차례 시작 때 있던 출력까지만 처리한다. 버퍼 속 바이트만으로 진행할 수 있는데 예산이 끝나면 **실행 가능**으로 다음 회차에 다시 부른다.
- accept는 회차마다 시도 수 상한까지만 한다.
- 이유·한계: 한 연결이 큰 파일·본문을 독점하지 못한다. 실시간 공평성은 보장하지 않는다. D-07 밖 accept 오류(`EMFILE` 포함)는 서버를 끝낸다(Step 7).
- 버린 선택지: `poll`, 엣지 트리거.
- 구현 내부 선택이다.

### D-57. 연결 상태를 구조체로 옮기고, 루프와 연결 처리를 나눈다 (D-46 대체)
- 선택: **루프 모듈**이 `epoll`·accept·연결 목록·마감 확인·끝난 연결 정리를 맡고, `http_conn`은 연결 하나의 상태 전이만 맡는다. 서버 경로에서 `http_conn_serve`는 없어진다.
- 끝난 연결: 즉시 끝 표시하고 다시 실행하지 않으며, 파일 fd 닫기 → 소켓 `close` → 메모리 해제는 **회차 끝**에 한다. 생성·등록 변경 실패는 그 연결만 `ERROR`로 끝내고, `epoll` 만들기·기다리기(`EINTR` 제외) 실패와 D-07 밖 accept 오류는 서버를 끝낸다.
- HUP·ERR: 종료 판정이 아니라 깨우는 정보다. 남은 입출력을 상태대로 처리하고 실제 `read`·`write` 결과로 기록한다.
- 이유: 지역 상태가 차례 사이에도 살아야 해서 구조체 필드로 옮긴다.
- 구현 내부 선택이다.

### D-58. 응답은 연결별 출력 버퍼에 만들고 나눠 보낸다
- 선택: 연결마다 **출력 버퍼**(64KB)에 `100`·머리·상태 본문·파일 조각·`/echo` 본문을 넣고 논블로킹 `write`로 보낸다. 출력이 남아 있으면 **새로 읽지 않고**, 모두 보낸 뒤에만 다음 내용을 채운다.
- 닫는 코드(D-51)는 최종 출력을 다 보낸 뒤 `shutdown(SHUT_WR)` 한 번 하고 정리(D-54)를 시작한다. 파일이 줄어 남은 길이가 있는데 끝이면 `EIO`로 `ERROR`이고, 머리 뒤 실패는 연결만 닫는다(D-29).
- 이유: 블로킹 쓰기를 남기면 받아 가지 않는 클라이언트 하나가 서버 전체를 멈춘다.
- 버린 선택지: `sendfile`(D-22·D-29 경로 변경, `/echo`에 못 씀), 응답 전체를 메모리에 만들기.
- 구현 내부 선택이다.

### D-59. 읽기·쓰기 진행이 없으면 5초 뒤 닫는다 (D-40·D-53의 시간 측정 변경)
- 선택: 논블로킹 연결에서는 `SO_RCVTIMEO`·`SO_SNDTIMEO` 대신 **읽기·쓰기 진행이 없는 기간 5초**를 연결별 단조 시계로 잰다. 결과 구분(D-53)은 유지하고 요청·응답 전체 마감은 두지 않는다.

| 실제 대기 | 만료 결과 |
| --------- | --------- |
| 요청 사이 읽기 (버퍼 비어 있음, 출력 없음) | `DONE` |
| 요청 도중 읽기 (머리·버릴 본문·`/echo` 본문, 출력 없음) | `TIMED_OUT` |
| 쓰기 (출력 남음, 논리 상태와 무관) | `ERROR` (`EAGAIN`) |
| 닫기 전 정리 (D-54) | `DONE`, 정리 시작부터 5초 고정 |

- 마감은 대기 종류가 바뀔 때마다 그때부터 새로 잡고 성공한 `read`·`write`만 갱신한다. 준비 알림·`EAGAIN`·`EINTR`·내부 실행은 늘리지 않는다.
- 준비·만료가 겹칠 때(사용자 선택): 이번 `epoll_wait`가 돌려준 준비 연결을 먼저 처리한 뒤 마감을 확인한다. 5초가 지난 뒤라도 실제 바이트 진행이 있으면 이어서 처리하고, 진행 없는 알림은 기존 마감을 유지한다. 정리는 고정 마감을 먼저 확인한다.
- 영향: 다른 연결을 처리한 시간도 센다. 받아 가지 않는 클라이언트는 마지막 쓰기 진행 뒤 5초 이후 루프가 확인할 때 닫히며(Step 4의 약 10초는 호출별 제한의 결과), 총시간 상한이 없고 정확한 5초 종료는 보장하지 않는다.

## 검토 결과

- D-56~D-58은 전체 구현 위임 안의 내부 선택이다(별도 정책 승인이 아니다). D-59의 정책·준비 우선 순서는 사용자 선택이다.
- 구현 영향·필수 기능 시험은 독립 검증을 통과했다. 설계 검토의 차단(B1·B2)은 해소, C1~C4는 조건부 반영됐다.
- 미검증 가정: 연결 fd를 `dup`하지 않아 마지막 `close`가 `epoll` 등록도 지운다. 연결당 메모리 약 82KB와 마감 확인 지연은 시험 규모(`ab -c 50`)에서 문제없다고 가정했다.
