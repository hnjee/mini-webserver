# Step 1. TCP 에코 서버

## 목표

클라이언트가 보낸 바이트를 그대로 돌려주는 서버를 만들어요. 요구사항 ID는 R-01이에요.

- `socket()` → `setsockopt(SO_REUSEADDR)` → `bind()` → `listen()` → `accept()` 흐름을 직접 구현해요.
- `nc localhost 8080`으로 입력한 글자가 그대로 돌아와요.
- 서버를 끄고 바로 다시 켜도 `bind()`가 실패하지 않아요.

HTTP는 아직 다루지 않아요. "연결 받기 → 읽기 → 쓰기" 통로가 뚫리는지만 확인해요.

## 핵심 과제

1. **듣는 소켓 준비**: Step 0에서 받은 `cfg.port`로 소켓을 열고 연결을 기다려요.
2. **연결 처리**: `accept()`로 연결을 하나 꺼내고, `read()` 반환값에 따라 돌려주거나 닫아요.
3. **재시작**: `SO_REUSEADDR`로 `TIME_WAIT`가 남아 있어도 바로 다시 `bind()`할 수 있게 해요.

## 질문과 정리

**Q. "소켓을 만든다"는 건 정확히 무슨 뜻인가?**

소켓은 커널(OS) 안에 생겨요. `socket()`은 커널에 소켓을 만들어 달라고 부탁하는 시스템 콜이에요. 서버 프로그램이 받는 건 그 소켓을 가리키는 번호, 즉 파일 디스크립터(fd)예요. 그 뒤로는 `bind(fd, ...)`, `read(fd, ...)`처럼 번호로 커널에 일을 부탁해요. 0, 1, 2는 stdin, stdout, stderr가 쓰고 있어서 보통 3부터 받아요.

**Q. `accept()`는 왜 `listen_fd`를 그대로 쓰지 않고 새 소켓(`client_fd`)을 주나?**

`listen_fd`는 연결 요청을 받아 대기열에 넣는 역할만 해요. 데이터를 주고받으려면 연결마다 송수신 버퍼와 상태가 따로 있어야 해요. 연결은 (클라이언트 IP, 클라이언트 포트, 서버 IP, 서버 포트) 네 가지 조합으로 구분해요. 그래서 서버 포트가 모두 8080이어도 연결마다 소켓이 따로 있을 수 있어요.

**Q. 연결 소켓은 언제 만들어지나?**

3-way handshake가 끝나는 순간 커널이 송수신 버퍼까지 갖춘 연결 소켓을 만들어 accept 대기열에 넣어요. `accept()`는 대기열에서 하나를 꺼내 fd 번호를 붙여 돌려줄 뿐이에요. 그래서 `accept()`를 부르기 전에도 handshake는 끝나 있고, 클라이언트가 보낸 데이터는 수신 버퍼에 쌓여요.

**Q. 서버를 껐는데 왜 `bind: Address already in use`가 나나?**

TCP에서 먼저 연결을 끊은 쪽은 바로 사라지지 않고 `TIME_WAIT` 상태로 잠깐(30초~2분) 남아요. 마지막 ACK가 유실됐을 때 다시 응답하고, 옛 연결의 늦은 패킷이 새 연결에 섞이지 않게 하려는 거예요. 서버 프로세스가 죽으면 커널이 소켓을 대신 닫는데, 이때 서버가 먼저 끊은 쪽이 돼요. 그래서 그 연결이 `TIME_WAIT`로 8080을 붙잡고 있는 동안 새 서버의 `bind()`가 거절돼요.

**Q. 그럼 `SO_REUSEADDR`는 무엇을 위한 것인가?**

서버를 껐다가 바로 다시 켤 수 있게 하려고 써요. "`TIME_WAIT`로 남은 연결이 있어도 이 포트에 `bind()`를 허락해줘"라는 옵션이에요. `TIME_WAIT`가 없어지는 건 아니고, 새 서버가 같은 포트에서 `listen`하는 것만 허락해줘요. 새 연결은 클라이언트 포트가 다른 새 조합이라 옛 연결과 섞일 일이 거의 없어요. `bind()`보다 먼저 설정해야 해요.

**Q. `read()`의 반환값 `n`은 무엇을 뜻하나?**

성공/실패가 아니라 "몇 바이트 읽었는지"예요.

| `n` | 뜻 | 에코 서버가 할 일 |
| --- | --- | --- |
| 양수 | `n`바이트를 읽었어요 | 읽은 `n`바이트만 돌려줘요. `sizeof(buf)`를 보내면 쓰레기 값까지 나가요 |
| 0 | 상대가 연결을 끊었어요 (EOF) | `close(client_fd)` 하고 다음 연결을 받아요 |
| -1 | 에러예요. 원인은 `errno`에 있어요 | `EINTR`이면 다시 읽고, 그 밖에는 연결을 닫아요 |

**Q. 터미널 두 개에서 동시에 `nc`로 접속하면?**

연결은 둘 다 돼요. handshake는 커널이 해주니까요. 하지만 서버 코드가 첫 번째 연결의 `read()`를 기다리느라 `accept()`를 다시 부르지 못해요. 두 번째 연결이 보낸 글자는 수신 버퍼에 쌓이기만 하고, 첫 번째 연결이 끊기면 그때 한꺼번에 돌아와요. 이 한계는 Step 5(동시성)에서 해결해요.

## 이 단계에서 정한 것

| # | 결정 | 이유 |
| - | ---- | ---- |
| 1-1 | `socket()` → `setsockopt(SO_REUSEADDR)` → `bind()` → `listen()` → `accept()` 반복 흐름으로 만든다. | 과제의 필수 구현 흐름이에요. (DESIGN.md 제안과 같음) |
| 1-2 | `SO_REUSEADDR`는 `bind()` 전에 켠다. | 켜지 않으면 재시작할 때 `TIME_WAIT` 때문에 `bind()`가 실패해요. (DESIGN.md 제안과 같음) |
| 1-3 | IPv4(`AF_INET`)로, 모든 네트워크 주소(`INADDR_ANY`)에서 연결을 받는다. 포트는 `htons(cfg.port)`로 넣는다. | 과제 테스트는 IPv4로 충분해요. `127.0.0.1`에만 묶으면 Docker 포트 연결로 들어오는 Mac의 요청을 못 받아요. 소켓 주소는 네트워크 바이트 순서(빅 엔디언)여야 해서 `htons()`로 바꿔요. |
| 1-4 | `listen()`의 대기열 길이는 `SOMAXCONN`으로 한다. | OS가 허용하는 최대값이라, 순간적으로 연결이 몰려도 대기열에서 거절될 일이 적어요. |
| 1-5 | 한 번에 연결 하나만 처리하는 반복 서버로 만든다. | Step 1은 통로 확인이 목적이에요. 동시 처리는 Step 5에서 방식을 골라 붙여요. |
| 1-6 | `read()`가 양수면 그 바이트만 돌려주고, 0이면 연결을 닫고, -1이면 `EINTR`은 다시 읽고 나머지는 연결을 닫는다. | 반환값의 뜻을 그대로 따르는 처리예요. (DESIGN.md 제안과 같음) |
| 1-7 | 쓰기는 `write_all()`로 `n`바이트를 끝까지 보낸다. | `write()`는 요청한 것보다 적게 쓰고 돌아올 수 있어요. Step 2의 응답 전송에도 그대로 써요. |
| 1-8 | 서버 준비 단계(`socket`, `setsockopt`, `bind`, `listen`)가 실패하면 `perror()`를 출력하고 종료 코드 1로 끝낸다. `accept()` 실패는 출력만 하고 다음 연결을 기다린다. 연결 하나의 에러는 그 연결만 닫는다. | 준비가 안 되면 서버를 돌릴 수 없지만, 연결 하나의 문제로 서버 전체가 멈추면 안 돼요. |
| 1-9 | 읽기 버퍼는 4096바이트 지역 배열로 한다. | 에코는 받은 만큼 바로 돌려주니 크게 잡을 필요가 없고, `malloc()`·`free()`를 맞출 필요도 없어요. |
| 1-10 | 연결을 받거나 닫을 때 클라이언트 IP와 포트를 `stdout`에 출력한다. | 터미널 두 개로 접속할 때 어느 연결이 처리 중인지 눈으로 확인할 수 있어요. |
| 1-11 | 소켓 코드는 `server.c`/`server.h`로 분리하고, `main.c`는 설정을 읽은 뒤 서버 함수를 부르기만 한다. | Step 2부터 에코 대신 HTTP 처리 함수로 바꿔 끼우기 쉬워요. |
| 1-12 | `SIGPIPE` 처리는 Step 7로 미룬다. | 클라이언트가 끊긴 뒤 `write()`하면 서버가 종료될 수 있다는 걸 알고 넘어가요. R-09는 Step 7 요구사항이에요. |

## 만드는 파일과 함수

| 파일 | 내용 |
| ---- | ---- |
| `src/server.h` | 서버 함수 선언 |
| `src/server.c` | 듣는 소켓 열기, `accept()` 반복, 에코 처리 |
| `src/main.c` | 설정 출력 대신 `server_open()`과 `server_run()`을 불러요 |

`server.c`의 함수예요.

| 함수 | 하는 일 |
| ---- | ------- |
| `server_open(port)` | `socket()` → `setsockopt()` → `bind()` → `listen()`을 하고 `listen_fd`를 돌려줘요. 실패하면 -1을 돌려줘요 |
| `server_run(listen_fd)` | `accept()`를 반복해요. 연결마다 클라이언트 주소를 출력하고 `handle_echo()`를 불러요 |
| `handle_echo(client_fd)` | `read()` 반환값에 따라 돌려주거나 연결을 끝내요. 끝나면 `close(client_fd)`를 해요 |
| `write_all(fd, buf, len)` | `len`바이트를 다 보낼 때까지 `write()`를 반복해요. `EINTR`이면 다시 쓰고, 그 밖의 에러면 -1을 돌려줘요 |

## 완료 테스트

모든 명령은 컨테이너 안에서 실행해요. 터미널 A, B, C는 각각 Mac 터미널에서 `docker compose exec dev bash`로 연 컨테이너 셸이에요.

> **실행 전에 프롬프트를 확인해요.** `dev@xxxx:/app$`면 컨테이너, `lhj@...MacBookAir`면 Mac이에요.
>
> | 증상 | 원인 | 해결 |
> | ---- | ---- | ---- |
> | `zsh: exec format error: ./webserver` | Mac에서 리눅스용 실행 파일을 실행했어요 | `docker compose exec dev bash`로 컨테이너에 들어가서 실행해요 |
> | `Cannot connect to the Docker daemon` | Docker Desktop이 꺼져 있어요 | Docker Desktop을 켜고 `docker compose up -d`를 실행해요 |
> | `service "dev" is not running` | 컨테이너가 꺼져 있어요 | Mac 터미널에서 `docker compose up -d`를 실행해요 |
> | 컨테이너에서 빌드나 링크 에러가 나요 | Mac에서 `make`를 돌려서 Mac용 빌드가 섞였어요 | 컨테이너에서 `make clean && make`를 실행해요 |

**1. 에코** (터미널 두 개)

```sh
# 터미널 A
make && ./webserver -p 8080 -r ./www
# → listening on port 8080

# 터미널 B
nc localhost 8080
hello        # 입력하면
hello        # 그대로 돌아와요
# Ctrl+C로 nc 종료 → 터미널 A에 연결 종료 로그가 나와요
```

**2. 바로 재시작**

```sh
# 터미널 B에서 nc localhost 8080으로 접속해 둔 채로
# 터미널 A에서 Ctrl+C로 서버 종료 → 바로 다시 실행
./webserver -p 8080 -r ./www
# → bind 에러 없이 listening이 나와요
```

서버가 먼저 끊어야 서버 쪽에 `TIME_WAIT`가 생겨요. 그래서 `nc`를 연결해 둔 채로 서버를 꺼요. 꺼진 직후 `ss -tan | grep 8080`을 실행하면 `TIME-WAIT` 줄이 보여요.

**3. 포트 충돌** (종료 코드 1)

```sh
# 서버가 켜져 있는 상태에서 터미널 B에서 하나 더 실행
./webserver -p 8080 -r ./www
# → bind: Address already in use, echo $? 는 1
```

`SO_REUSEADDR`는 `TIME_WAIT`만 허락해요. 이미 `listen` 중인 포트에는 여전히 `bind()`가 실패해요.

**4. 관찰: 두 번째 연결은 기다려요** (통과 조건은 아니에요)

```sh
# 터미널 B, C에서 각각 nc localhost 8080
# B가 접속해 있는 동안 C에 입력한 글자는 돌아오지 않아요
# B를 끊으면 C의 글자가 한꺼번에 돌아와요
```

**5. 비교 실험** (선택)

`server_open()`의 `setsockopt()` 줄을 주석 처리하고 테스트 2를 다시 해 보세요. `bind: Address already in use`가 나오면 `SO_REUSEADDR`가 하는 일을 확인한 거예요. 실험이 끝나면 주석을 되돌려요.
