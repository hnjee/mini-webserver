# 후속 확장 결정 기록: 작업 큐 + 워커 스레드 풀

이 문서는 작업 큐·워커 스레드 풀 확장의 설계 결정과 그 근거를 기술하는 것을 목적으로 한다.

- 진행 상태: [README.md](./README.md)
- 상태: 사용자 확정 2건 밖은 모두 `임시` (설계 재검토·구현·독립 코드 검증 완료). 채택하면 D-번호를 부여하고 [전체 결정 색인](../../decisions.md)에 올린다.
- 사용자 확정: 루프는 연결 처리를 직접 하지 않는다 · 연결 하나는 동시에 워커 하나만 처리한다.
- 구조·불변조건·루프 회차·실패 표는 [README](./README.md)를 본다. HTTP 동작은 바꾸지 않는다.

## 결정

### 루프는 등록·마감·정리를, 워커는 차례 실행만 맡는다
- 선택: `epoll`·accept·등록 변경·마감 확인·만료·정리는 **루프 스레드만** 한다. 워커는 `http_conn_run` 한 차례를 실행하고 결과만 돌려준다. 공유 실행 상태는 큐 잠금으로 보호한다.
- 이유: D-57의 경계(루프 = 등록·수명, `http_conn` = 상태 전이)를 스레드 경계로 쓴다. 워커가 직접 다시 등록하는 안은 버렸다.

### 넣기 전에 유효한 등록을 모두 지워 연결당 워커 하나를 지킨다
- 선택: 큐에 넣기 전과 만료 처리 전에 클라이언트·백엔드 등록을 해제하고(세대가 다르면 `DEL` 없이 0), 완료 뒤 마지막 차례 결과대로 다시 `ADD`한다.
- 이유: 레벨 트리거는 계속 알려 헛돌고 같은 연결이 두 번 들어갈 수 있다. 만료 뒤에 해제하면 닫힌 fd에 `DEL`해 504가 `ERROR`로 바뀐다.
- 버린 선택지: `EPOLLONESHOT`(업로드 중 두 소켓에 맞지 않음), 등록을 둔 채 바쁨 표시로 거르기.
- 한계: 소켓당 `epoll_ctl`이 늘어 처리량이 Step 5보다 낮을 수 있다.

### 같은 배치의 두 소켓 알림은 합치지 않고 차례로 실행한다 (D-67 유지)
- 선택: 한 배치에 같은 연결의 클라이언트·백엔드 알림이 함께 오면 **배치 순서대로 한 차례씩** 실행한다. 보존한 백엔드 차례는 넣기 직전에 세대를 다시 확인하고, 앞 차례가 `FINISHED`면 뒤 차례를 버리며, 등록은 마지막 차례 결과로만 한다.
- 이유: 원인을 합치면 백엔드 머리 `read`가 예산을 써 클라이언트 본문 `read`가 빠지고 무진행 마감으로 잘못 닫힐 수 있다. D-67의 "각 실행은 자기 예산과 원인만큼" 계약을 지킨다.
- 버린 선택지: 원인 합치기, 뒤 알림 버리기(재등록 뒤 먼저 만료될 수 있음).

### 큐 대기 중에는 마감을 바꾸지 않고, 회수 직후 확인한다 (D-59 유지)
- 선택: `QUEUED`는 HTTP `RUNNABLE`과 다르며 `deadline`을 멈추거나 다시 잡지 않는다. 바쁜 연결은 만료 확인에서 빠지고 다시 등록된 직후 같은 회차에 확인한다.
- 이유: 큐 대기만으로는 닫히지 않고 D-59와 같다.
- 한계: 큐 대기 지연 상한은 보장하지 않는다.

### 완료는 완료 큐와 eventfd로 알린다
- 선택: 워커가 완료 큐에 넣은 **뒤** 논블로킹 eventfd에 쓰고, 루프는 eventfd를 읽은 **뒤** 완료 큐를 비운다. 쓰기 `EAGAIN`은 성공, `EINTR`은 재시도, 그 밖은 `abort`다. 읽기 `EAGAIN`은 무시, 그 밖은 서버를 끝내는 실패다.
- 이유: 깨우기 손실이 없고 논블로킹이라 종료 중에도 워커가 막히지 않는다.
- 버린 선택지: 짧은 시간 제한 폴링, 파이프.

### 라운드 로빈 카운터는 원자 증가로 바꾼다 (D-63 유지)
- 선택: `route_rule.next`를 원자 정수로 바꿔 고를 때 바로 증가한다. 라우팅 표의 나머지는 읽기 전용이다.
- 버린 선택지: 루프가 고르기, 규칙별 잠금.
- 한계: 동시 요청 사이의 선택 순서는 정해지지 않는다.

### 작업 큐는 연결 안의 연결 고리로 만들고 크기 제한을 두지 않는다
- 선택: 작업 큐·완료 큐는 연결 구조체 안의 연결 고리를 쓰는 FIFO이고 잠금·조건 변수 하나씩이다. 워커 수는 시작 때 정하는 상수(기본 4)다.
- 이유: 연결당 최대 한 칸이라 포화·할당 실패 경로가 없다. 포화 때 거절하는 정책은 사용자에게 보이는 동작이라 범위에 넣지 않는다.
- 버린 선택지: 고정 크기 원형 큐, 워커 수 실행 인자(사용법 변경).

### 시작 실패와 종료는 만든 워커만 멈춘 뒤 해제한다
- 선택: 서버를 끝내는 실패에서 정지 표시 → 워커 깨움 → 잠금을 놓고 **만든 워커만** `join` → 연결 해제 → eventfd·`epoll` 닫기 순서다.
- 이유: 먼저 해제하면 해제 뒤 사용, 잠금을 쥔 채 `join`하면 교착이다.
- 한계: 신호로 프로세스가 끝나는 경우는 이 정리를 하지 않는다(이 확장 시점 기준이며 신호 정리는 Step 7 D-69에서 다룬다).
