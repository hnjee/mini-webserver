# 테크니컬 라이팅 원칙

이 문서를 읽으면 이 저장소의 문서를 같은 기준으로 쓰고 검수할 수 있어요. PR의 문서 검수 봇도 이 문서만 기준으로 삼아요.

## 1. 한 페이지에서는 하나만 다루기

- 문서 하나는 주제 하나만 다뤄요. 주제가 둘이면 문서를 나눠요.
- 제목(H1)은 문서마다 하나만 써요.

## 2. 가치를 먼저 제시하기

- 문서 첫 문단에 "이 문서를 읽으면 …을 할 수 있어요"처럼 얻는 것을 먼저 써요.
- 배경 설명은 그 뒤에 써요.

## 3. 속성 설명에 의미와 형식 함께 쓰기

- 옵션, 설정 값, 헤더, 함수 인자를 설명할 때는 의미, 허용 형식, 예시를 함께 써요.
- 예: `-p` 서버가 열 포트 번호예요. 1~65535 정수예요. 예) `-p 8080`

## 문장 규칙

- 해요체로 써요. 설계 결정을 적는 문장만 "~한다"로 써요.
- 한 문장에는 한 내용만 써요.
- 같은 대상은 같은 용어로 불러요. (예: "요청 라인"을 "첫 줄"과 섞어 쓰지 않아요)
- 함수, 파일, 명령어, 헤더 이름은 백틱으로 감싸요. (예: `accept()`, `Content-Length`)

## 지적 형식 (리뷰어·봇 공통)

- 위치 / 문제 / 근거 / 수정안 / 심각도
- 심각도: 🔴 꼭 고칠 것, 🟡 고치면 좋은 것, 🟢 사소한 것
- 근거 없는 지적, 취향 문제는 쓰지 않아요.
